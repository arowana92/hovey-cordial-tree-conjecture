# Every finite tree is 25-cordial

**Theorem (computer-assisted).** Every finite tree admits a labeling modulo 25 in which the vertex-label frequencies differ pairwise by at most one and the edge-weight frequencies differ pairwise by at most one. Each edge weight is the sum of its endpoint labels, and the frequency comparisons include zero counts.

## From forests of order 24 to trees of every order

Apply the repository's ordered-cut theorem with $k=25$. Its base asks for a bijection on each tree of order 25 with 24 distinct edge sums. Its extension hypothesis concerns a forest of 24 free vertices with at most $\lfloor 2(25-2)/3\rfloor=15$ terminal vertices. Each component has an edge back to a vertex of the core with a prescribed label. In order of nondecreasing component size, a new run of boundary labels can begin only when the next component has size at least the sum of the previous component sizes plus the number of previous runs.

The core of order one modulo 25 has uniform edge counts and a unique surplus vertex residue, translated to zero. A forest witness uses the 24 nonzero residues and gives distinct weights on all 24 added edges, including the edges to the core. This restores the two balance conditions. A smaller final forest can be padded to 24 and its witness restricted. The tree-cut and leaf-deletion arguments guarantee one of these steps in a minimum counterexample. For the base, attaching a vertex labeled zero to all the component roots recovers each rooted tree of order 25 from the all-zero boundary case, including forests exceeding the terminal limit. This proves the theorem once both finite checks pass. [Cut, exact run condition and induction](ordered-cut.md) · [Leaf deletion and padding](README.md#why-the-hypotheses-suffice)

## Verification

The certificate generator searched for vertex permutations on every rooted shape. A single row can witness several colorings. The independent native verifier parses the ordered forest, checks the actual permutation and internal sums, and computes the possible incoming labels by assigning unused edge weights to distinguished roots of the component groups. It checks the other incoming edges and requires coverage of every permitted boundary assignment up to multiplication by a unit. The zero boundary is checked for every shape. The full audit sorted all canonical shape words across 2,048 shards, rejected duplication and checked the total against the rooted-tree recurrence. The sum of the generator's per-shard record and witness counts agreed with the verifier. [Generator](spine_generate.cpp) · [Verifier](spine_verify.cpp) · [SHA-256 manifest](spine25.sha256)

Three separate checks address different parts of the reduction.

- An integer-partition calculation recovered the exact base, eligible-forest and boundary-assignment totals. Independently ranking **every one** of the 2,067,174,645 generator shapes from its parent array also gave a bijection with the expected interval of ranks. The integer-labeling census gives a separate proof for the order-25 base. [Partition counts](spine_counts.py) · [Independent ranking proof](shape-rank.md) · [Integer census](../census/README.md)
- A Python checker enumerated subsets of actual component positions at which the boundary color changes and excluded collisions of the resulting edge sums. On shards 49, 53 and 57 it checked 75 sampled forests, 5,058 witness rows and 1,378,803 boundary inputs, including base-only records and each possible maximum run count from one through four. Each of the three retained files matched its manifest entry. Shards 49 and 53 also regenerated byte for byte from a separate SSH checkout. [Sample checker](check_spine_samples.py)
- Both native catalog-checking modes rejected seven deliberate faults, including a changed vertex, a truncated row, an empty record, incomplete coverage, a missing catalog and repeated shapes within and across files. [Fault tests and commands](shape-rank.md#checks)

## Reproduction

Use Python 3 and a C++17 compiler on a system with POSIX named pipes. The complete witness stream is 1,836,337,557,772 uncompressed bytes. The command below pipes the bytes directly from each generator through SHA-256 into the verifier. It uses the independent rank bit array, which needs about 246.4 MiB for global shape keys plus working memory. The original audit used the canonical-word sort, with about 15.4 GiB for global keys, and one temporary shard per generation worker. Removing the two optional flags reproduces that configuration. Both modes check the same witnesses and produce the same stream digests. The output directory passed to the runner must be new.

~~~sh
set -e
src="$PWD/research/rainbow"
out=$(mktemp -d)
c++ -O3 -std=c++17 -c -Drainbow_witness=reference_witness "$src/search.cpp" -o "$out/reference.o"
c++ -O3 -std=c++17 "$src/spine_generate.cpp" "$src/leaf_search.cpp" "$out/reference.o" -o "$out/generate"
c++ -O3 -std=c++17 -pthread "$src/spine_verify.cpp" -o "$out/verify"
python3 -B "$src/stream_spine.py" 25 2048 12 "$out/generate" "$out/verify" "$out/audit" --pipe-witnesses --rank-bits
cmp "$out/audit/spine25.sha256" "$src/spine25.sha256"
cat "$out/audit/verified.txt"
python3 -B "$src/spine_counts.py" 25
~~~

For a one-shard replay, use the same binaries and run the following. The retained sample checker scans the whole file and checks selected forests in detail.

~~~sh
cd "$out"
mkdir spine25
./generate 25 53 2048 spine25/53.spn --ranked-cover
awk '$2 == "spine25/53.spn"' "$src/spine25.sha256" | shasum -a 256 -c -
python3 -B "$src/check_spine_samples.py" spine25/53.spn
~~~

## A finite pilot for 26

At modulus 26, shard 53 with stride 524,288 contains 10,986 shapes and 709,471 witness rows. Its SHA-256 is `409a9ceb99f82f1a82ed6d15922ba56cb876a302607d80b90f8ba625d22d3637`. Generation to disk and generation through a pipe agreed. The native verifier accepted all local witness and coverage checks and reported an incomplete catalog at its final count, as expected for one shard. An independent Python pass examined every record and every witness in this pilot. It checked 55,865,961 boundary assignments by enumerating the actual positions at which a color can change. A separate exhaustive topology pass ranked all 5,759,636,510 shapes without duplication. The [rank proof and command](shape-rank.md#checks) verify the shape inventory independently of the local labeling checks. This pilot is finite evidence for 26. The theorem above is for 25, and Hovey's conjecture over all moduli remains open.

~~~sh
./generate 26 53 524288 pilot26.spn --ranked-cover
shasum -a 256 pilot26.spn
python3 -B "$src/check_spine_samples.py" pilot26.spn --stride 1
~~~

At stride 4,096, shard 53 has 1,406,162 shapes and 90,562,434 rows (2,280,934,799 bytes). From a separate SSH checkout the regenerated file had SHA-256 `be107ef66279a8e91b1fd00bde3b4638cadd2d809572f32e3d5804ca5af61f41`. A separate native build finished all local checks and then reported the expected incomplete catalog. The Python checker sampled 33 shapes, 3,968 rows and 572,183 boundary assignments, spanning run counts zero through four. The full audit at 26 is in progress.
